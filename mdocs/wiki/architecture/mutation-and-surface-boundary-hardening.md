# Lossless mutations and surface boundary checks

## Flat initiative writes
Existing paths are stable identities for updates: do not run filename formatting after reading an existing flat record. Patch only changed managed frontmatter keys and known sections; preserve unknown sections, custom frontmatter, multiline/lazy list entries, fenced examples, newline style, and Markdown hard-break spaces. Progress append must preserve old entries. The public manager API can still explicitly update known body sections. Completion, graduation, and wiki links reuse this writer. Atomic sibling-file replacement leaves the original intact if replacement fails.

Wiki metadata updates retain the original body bytes when content is unchanged. Managed Referenced By removal is section-bounded and must not truncate a consumer appendix. CRLF frontmatter must be removed correctly when reading the model.

## Command boundary
SUPPORTED_COMMANDS is one frozen tuple for runtime dispatch, provider enums, and descriptions. OpenCode and shared Claude/Kimi MCP use Zod enums; pi publishes the same enum through TypeBox. Schema bypasses receive success=false, code=INVALID_COMMAND, retryable=true, the received command, error, and supportedCommands. MCP rejects an invalid command before constructing project memory. Host error signaling must remain intact.

## Kimi launch
Kimi resolves MCP arguments from the session project cwd, not plugin root. The manifest uses a portable inline Node launcher that locates the managed bundle under KIMI_CODE_HOME (default ~/.kimi-code), plugins/managed/mdocs/dist/mcp-server.js, then starts its exported server without changing cwd. This avoids both project-relative MODULE_NOT_FOUND and a plugin-root cwd fix that would silently target the wrong memory tree. Reinstall/reload after an update. Test the actual managed manifest from an unrelated project, including initialize, tools/list and project lookup.

## Curated compiled views
compiledViewMutationMode=targeted is a separate explicit capability. External ownership alone remains read-only. index.sync registrations target one initiative directory, wiki catalog entry, or active-initiative overview row. Existing curated rows and annotations remain unchanged; only package-marked rows are refreshed. Exclude comments/fenced examples from membership and row ownership. Validate the whole batch first, replace individual files atomically, verify membership from disk, and report rollback failures. This is not a crash-atomic multi-file transaction. Creation returns explicit requiredFollowUps rather than claiming compiled views were registered.
