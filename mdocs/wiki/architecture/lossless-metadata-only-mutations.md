## Summary
GitHub issue #8 P0 implementation makes wiki and initiative mutations safe over directory-v2 consumer schemas with `initiativeRecordMode: metadata-only`.

## Design
- `WikiEntry` now supports `status` and retains raw frontmatter metadata during parse/update.
- Wiki writes merge managed fields into original frontmatter lines. Unknown fields, aliases such as `sources`, path-style IDs, singular categories, body content, and line endings remain intact.
- Metadata-only initiative links use surgical `related_wiki` frontmatter-array updates rather than normal initiative persistence, which intentionally ignores structural fields in that mode.
- `wiki.link` reads back both sides before declaring a bidirectional link, rolls back initiative-side change if wiki-side mutation fails, and skips own compiled-page self-links.
- Command inputs normalize known snake_case/camelCase aliases. Mutation results expose `appliedFields`, `skippedFields`, and `unsupportedFields`; unsupported fields fail explicitly, while metadata-only ignored fields are reported as skipped.
