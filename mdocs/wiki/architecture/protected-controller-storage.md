## Purpose
WP-200 supplies host-controlled authority storage for effectful Run. Project files and mirrors never grant authority.

## Model
- `ProtectedStoreAdapter` owns atomic snapshots, physical revisions, writer generations, logical generations, append high-water marks, and recovery markers.
- `ProtectedControllerStore` validates canonical envelopes, checksums, schema versions, fencing, rollback, and compare-and-swap conditions before exposing authority.
- Writes atomically compare writer generation, physical revision, logical generation, and append sequence/high-water state.
- Corruption or metadata rollback preserves raw bytes, quarantines by observed physical revision, and returns recovery-required or incompatible state. Concurrent recovery is reinspected rather than overwritten.

## Serialization limits
Canonical JSON copying uses null-prototype objects and preserves keys such as `__proto__` without invoking setters. Encoded bytes, decoded depth, node count, strings, and arrays are bounded. Final stored envelope size is checked before mutation.

## Project mirror
Mirror data is non-authoritative and uses finite state/reason enums plus fixed bounded counters. Arbitrary text, authority handles, credentials, receipts, and full controller state are rejected.

## Compatibility facade
Legacy `ControllerStore` delegates to protected storage. Writers open lazily; caller inputs are synchronously canonical-snapshotted before awaits. Per-key append serialization prevents healthy same-facade contention while protected CAS remains authority.

## Production boundary
`InMemoryProtectedStoreAdapter` and fake trusted adapters are test fixtures, not production protected storage. Production Run remains plan-only until a host adapter proves isolation, durability, fencing, and recovery behavior.
