## Summary
GitHub issue #8 P1 adds contract-aware, read-only validation diagnostics for directory-v2 consumer schemas. Post-0.8.0 feedback identified compatibility regressions corrected for the next patch release.

## Rules
- Directory initiative validation discovers immediate `initiatives/*/_status.md` records.
- In `initiativeRecordMode: metadata-only`, directory identity is authoritative; manager and linter validation do not require `id` or `title` in `_status.md`. Lifecycle fields remain validated.
- Active directory initiatives require a compiled `wiki/initiatives/<id>.md` (or compatible singular-category) page with status matching normalized source status.
- Metadata-only directory consumers may keep semantic categories on root compiled views `overview.md`, `index.md`, `log.md`, and `glossary.md` when category equals filename stem. Runtime identity remains bare root ID; arbitrary root categories and mismatches remain errors.
- Semantic root compatibility does not depend on wiki index mode. Default full-record behavior remains strict.
- With `wikiIndexOwner: external`, curated `wiki/index.md`, `initiatives/INDEX.md`, and `wiki/overview.md` are parsed read-only. Missing link membership is reported without rewriting any compiled view.
- Markdown destinations and closed inline-code path entries are accepted. Categorized artifacts require category-qualified references; bare IDs mean root pages only.
- Graph validation detects asymmetric links, self links, alias-mediated self links, identity/category mismatches, and source/page status drift while preserving valid path-style IDs and singular category aliases.
- `wiki.ingest` fails aggregate success when an operation fails. `wiki.xref` validates exact existing targets and reports directed semantics accurately.
