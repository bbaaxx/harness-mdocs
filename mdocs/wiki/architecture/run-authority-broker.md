## Purpose
WP-210 supplies the effectful Run authority boundary: opaque ticket broker, attenuation, controller/workstream leases, and hierarchical budget ledger over protected storage.

## Model
- `createRunAuthorityManager` composes protected-store repository, ticket broker, leases, budgets, and recoverable provider sagas. Only module-private records resolve opaque handles; prompt text, env vars, agent names, and caller-cast objects never authorize.
- `delegation-ticket/v1` fields derive from validated compiled graph, not caller claims. Stored aggregate binds project/run, plan+graph digests, graph revision/epoch, cancellation generation, and verified approval/mode refs.
- Strict topology: root→EO→leaf only. Component-wise attenuation for write sets, criteria, operation/tool/credential classes, approvals, budgets, expiry, depth, fanout. Child never widens.
- Leases: one controller per run, one per workstream; defaults TTL 60s / heartbeat 15s; injected wall+monotonic clocks with per-domain high-waters; fenced takeover invalidates stale holders and binds child workstreams to controller fence.
- Budgets: hierarchical ledger covering all 18 plan dimensions; parent reserves child capacity before ticket issuance; EO subdivides own reservation only; global caps override subtree; retries/replacements/resumes consume cumulative counters; token/cost/action reconciliation requires authoritative `UsageMeter` with idempotent reserve/commit/release keyed by deterministic scope.
- Replay/expiry/cancellation: single-use nonce, restart-persistent handle lookup, expiry boundary denial, graph epoch and cancellation generation mismatch revokes before effects/spawns.

## Security boundaries
- Trusted `HumanAttestationProvider`, `HostIdentityProvider`, and `AuthorityUsageMeter` injected in manager options only; caller never supplies provider, holder, or usage samples.
- Two-phase initialization: protected pending reservation → verifyPair → finalize; idempotent across concurrent callers and crash recovery. Pending attestation cannot wedge a run; typed recovery (`abortPendingIssuance`, `reconcileUsage`, `releaseReservation`).
- Root permissions derive solely from digest-bound compiled plan policy; no caller root-authority input. Reconciliation returns persisted committed result without resampling; provider scope is opaque and host-issued.
- Safe barrel exports manager factory, lease records, provider interfaces, and redacted inspection types only. Test factories, crypto injection, raw broker internals, and reusable resolved authority never cross the package boundary.
- Recovery semantics: corruption/incompatible/recovery-required state never authorizes; orphan provider release never touches live ticket usage; in-flight same-provider bind is stabilized, not stolen; claimed reservations settle best-effort on cancel with bounded timeout and explicit unsettled reporting.

## Production boundary
No production surface registers authority providers in WP-210. Effectful Run remains plan-only until trusted adapters prove attestation, identity, metering, and lease fencing through WP-300 probes.
