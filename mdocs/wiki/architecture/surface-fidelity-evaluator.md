## Purpose
WP-300 converts host-observed probe transcripts into separate Route and Run fidelity decisions. Declared support never upgrades measured support.

## Trust boundary
Only an internal host registry and killable-isolation executor can mint opaque trusted measurements. Public barrels expose catalog, strict schemas, and evaluator only; runner authority, executors, probes, and fake adapters remain unexported. TypeScript types are not a security boundary.

## Probe execution
- Probes execute sequentially with unique sandbox paths and fresh challenges.
- Runner verifies challenge echo, stamps host time, canonicalizes assertions, and rejects duplicate probe IDs/assertions.
- One monotonic deadline covers result and natural process settlement.
- Passing evidence is accepted only after isolated process settles cleanly.
- Timeout, rejection, forced termination, failed drain, or an undrained process yields unknown; undrained execution poisons the runner and caps all Run evaluations, including older snapshots, at plan-only.
- Adapter results and evaluator requirements are bounded before Zod traversal; hostile proxies, accessors, sparse arrays, oversized assertions, and extra requirement keys fail closed.

## Evaluation
Route and Run are independent. `route.contracts` affects Route only. Run evaluates trusted attestation, identity, protected storage, action mediation, receipts, delegation depth, cancellation, and conditional token/cost metering. Missing or malformed requirements return `RUN_REQUIREMENTS_INVALID`; human checkpoints produce supervised fidelity with an explicit reason. Every downgrade has a canonical reason.

## Production boundary
No production surface registers an executor in WP-300. Therefore current production effectful Run remains plan-only. Host-specific adapters must later prove killable isolation and all required probes.
