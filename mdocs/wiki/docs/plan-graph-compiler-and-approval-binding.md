## Compiler Boundary

`src/agents/run/compiler/` is pure. It has no filesystem, clock, randomness, persistence, scheduler, ticket, lease, action, or surface dependency.

Ingress is strict and bounded:

- duplicate-key-safe raw JSON parsing before Zod;
- strict object schemas and descriptor-safe programmatic input validation;
- finite raw bytes, string lengths, array sizes, total values, and depth;
- rejection of accessors, cycles, sparse/oversized arrays, custom prototypes, non-I-JSON values, C0/C1/DEL/bidi controls, and unsafe write selectors.

## Deterministic Compilation

Normalization trims and validates strings, sorts/deduplicates set-like arrays by UTF-16 order, topologically sorts milestones with lexical ties, applies conservative budgets, and never mutates caller input.

Stable nodes use collision-free length-prefixed explicit keys. Generated hierarchy is fixed:

```text
PLAN_ROOT milestone -> EXECUTION workstream -> LEAF work
```

Milestone dependencies remain immutable plan semantics because orchestration artifact edges represent delegation roles only. Root-owned milestone/global integration nodes are gates, not delegation edges. EO/leaf overlap remains serialized until later trusted isolation proof exists.

Write authority attenuates syntactically: milestone selectors fit approved scope and avoid out-of-scope; workstreams fit milestones; leaves fit workstreams. Compiler enforces per-EO leaf and cumulative-spawn budgets.

Compilation validates and seals `execution-plan/v1`, then builds `orchestration-artifact/v1` with exact `planDigest`, validates/seals it, verifies both envelopes, and deep-freezes the compiled pair. Pair validation re-derives exact output from normalized source, rejecting graph mutation, extra/missing nodes, changed isolation/report kinds, duplicate edges, or bad binding.

## Approval Binding

Approval and execution mode are separate trusted events and have no default. Binding requires exact plan digest, graph digest, plan revision, principal, project, and host session.

`HumanAttestationProvider.verifyPair` authenticates and consumes both gestures atomically. Fake trusted provider checks issued object identity before reading fields, preventing forged Proxy/getter re-entry; failed pairs consume neither valid event. Challenges are globally one-shot, expiry is inclusive, revision/principal mismatches fail, and copied/mutated/synthetic events are rejected.

Project files, model/tool output, copied JSON, and prompt claims still cannot mint approval.
