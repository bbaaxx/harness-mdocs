## ProjectReadContext

`src/agents/project-context.ts` is Route's only filesystem boundary. It constructs no mutable mdocs manager, workflow engine, lifecycle service, audit log, command registry, or surface hook, and exposes no write API.

Policy:

- canonical real project root;
- project-relative lexical references only;
- no home, global, absolute, drive-prefixed, or parent-traversal references;
- contained symlinks allowed; escaping targets fail closed;
- fd-pinned regular-file reads with bigint identity/generation checks;
- bounded streaming reads/hashes;
- stable directory transactions retry once, then return `concurrent-mutation` without partial evidence;
- deterministic frozen list and snapshot results.

## Pure Route

`src/agents/route/` provides strict data-driven probe schemas, transactional project capability inventory, and deterministic `execution-blueprint/v1` generation.

Only active current-project runtime evidence, project config/manifest evidence, package-owned project assets, and explicit project declarations count. Surface metadata, home/global/cache files, environment variables, and process-global discovery do not prove availability.

Each capability axis remains independent: `installed`, `configured`, `exposed`, `permitted`, and task suitability. Selection requires every availability axis `confirmed` and suitability `suitable`. Missing, malformed, conflicting, unsafe, global, or concurrently unstable evidence remains absent/unknown and cannot upgrade eligibility.

Route brackets each relevant evidence reference with deterministic snapshots, retries one change, then fails closed. Set-like inputs and outputs are sorted/deduplicated before inventory and request digests. Runtime evidence binds to canonical project root. Future capabilities are injected through definitions/probes without editing Route core.

Blueprints are sealed, deeply frozen, schema/digest verified, and carry no approval, mode selection, ticket, handle, mutable progress, or effect authority. Side effects are exactly `none: Route is read-only`.
