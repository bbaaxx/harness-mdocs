## Objective
Extend `mdocs-orchestrator` with an extensible, surface-neutral capability model and two explicit user intents. `route` must inspect only project-scoped capabilities and produce an execution-ready blueprint without mutation. `run` must execute long-running initiative work through an explicit bounded, auditable, resumable policy profile that forecasts approvals and minimizes avoidable interaction. Project one coherent Orchestrator product across OpenCode, Claude Code, Codex, and pi while mapping honestly to each host and allowing future capabilities without adding one universal peer agent per feature.
